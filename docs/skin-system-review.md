# 原生皮肤 P0–P4 审查

审查日期：2026-10-05。基线为 `f9e4e95b` 及审查开始时的未提交工作树。范围包括五个内置皮肤、自由原生场景、JSON ZIP、本地包管理、开发样例及后续补充的原图/歌词/PCM/FFT、胶囊、hover、点击与拖动要求。Web、Folium、市场和开发目录监听仍属于后续阶段。

## 结论

原有方向成立：描述/登记、组件工厂、作者场景、包存储与领域服务有独立入口。新增场景不必修改普通/全屏宿主的皮肤 ID 分支；实时播放和分析保持在叶节点，歌词和分析继续使用唯一 owner。原实现存在明确的功能与生命周期缺口，不能直接视为 P0–P4 全部验收完成。本次在提交前修正它们。

| 阶段 | 源码覆盖 | 尚需区分的验收 |
| --- | --- | --- |
| P0 | 默认值、历史键、显示环境和迁移范围已有记录 | 五个内置皮肤、四类宿主的完整视觉/进出基线尚未记录 |
| P1 | 单一 catalog/descriptor、历史适配、开发登记样例；修正不支持可视化时错误换皮肤 | 实际旧配置恢复、全部内置默认值与来源回归 |
| P2 | 布局/控制/歌词协调拆分，会话 generation、任务取消、实例资源释放；共享 owner 保留 | 三条全屏进出、重复切换后的订阅/任务/渲染资源数量与视觉连续性 |
| P3 | Swift/JSON 场景、组件目录、自适应样例、唯一歌词挂载、重要参数、作者数据入口 | 宽窄/高矮/Retina、长文本、字体变化、所有来源与自绘输入实测 |
| P4 | 原生 ZIP 安装、资源持久化、导出、替换/副本、重启发现、设置内重载、删除、参数兼容 | 完整设置面板流程与三条全屏中的更新/删除；多版本回退尚未实施 |

P4 的本地功能补齐后，也不应把 P0/P2/P3 尚未完成的主 App 运行验收改写为通过。

## 提交前修正

| 问题 | 原行为/影响 | 修正 |
| --- | --- | --- |
| 重载没有读取包 | “刷新”只改变视图 ID；设置没有重载入口 | 服务重新读取安装 manifest、验证并发布；设置与场景右键共用同一入口 |
| 同 ID 更新没有会话失效 | 新定义进入列表，旧组件暂态/工作可能继续存在 | catalog 按身份发布 revision；全部使用中的宿主取消旧任务并重建皮肤内容 |
| 会话只管理任务 | 作者资源缺少共同的释放登记 | `registerCleanup` / `removeCleanup` 管理实例订阅/资源；自绘音频读取接入，共享服务仍由原 owner 管理 |
| 新组件默认成为整块交互区 | 内置背景等未列入固定“被动”名单时，可能遮挡原生歌词点击与顶部拖动 | 交互能力由组件登记，默认不圈整块区域；局部控件可自行声明矩形 |
| 自绘必要操作无法声明 | 无论自绘退出/Quick Panel 是否存在，宿主仍按“有没有左胶囊”重复补控件 | `skinProvidesControls` 合并操作声明；全屏只补缺失的退出、歌词开关和 Quick Panel |
| 隐藏普通场景仍重挂歌词 | fullscreen 期间更新隐藏场景，可能抢占 `.main` 视图 | 只在活跃场景挂载 native 歌词；普通 inspector 接管放在稳定宿主，避免重载子树的出现/消失顺序影响侧栏 |
| 旧场景无条件清配置 | 旧实例消失可能清掉新实例刚应用的歌词样式 | 作者覆盖带实例 owner；清理只针对自己的登记，新场景可显式接管空覆盖 |
| 停止后的音频帧仍可能发布 | 已入队的旧回调在重新订阅后写入新实例状态 | feed generation 丢弃退役订阅的帧 |
| 参数升级与非法范围 | 改类型/移除选项后仍读取旧值，反向范围可能导致设置 Slider 崩溃 | 安装前检查定义；兼容值保留，数值限到新范围，不兼容值采用新默认 |
| 局部描述覆盖无法解码 | 合法的少量 audio/presentation/artwork 字段因缺省键被拒绝 | 省略字段继承默认；显式 Coding 保持读写对称 |
| 可视化能力改变皮肤身份 | 不支持 Mini Player 可视化时配置退回 Classic LED | 保留所选身份，关闭不支持的可视化；历史 LED 开关保留原键输入 |
| P4 删除缺失 | 没有用户包删除流程 | 设置确认删除；相关普通/全屏选择恢复默认内置皮肤，播放继续；内置原件不可删除 |
| 契约没有 Schema | 作者只能依赖叙述与示例 | 增加原生 v1 JSON Schema，分别记录包格式、宿主 API 和作者版本 |

空渲染定义、未知组件、不支持的格式/API、重复参数/同级节点及多个同时可见 native 歌词，在发布安装前报告。新包准备失败不删除旧安装，失败重载不变更 catalog revision 或当前定义。原生 v1 使用同步定义准备；没有宣称完成 Web 脚本运行错误恢复。

## 作者约束与扩展边界

必要播放操作、进度/音量、歌词开关、进入/退出全屏与 Quick Panel 可以由作者自绘并调用现有动作，也可以采用官方组件。各有效自适应分支都必须保持必要操作可达。完整 Mini Player 自带左右胶囊，不登记中间胶囊；单独调用左右胶囊时要求成对出现。这些要求写入作者交付约束，不按固定组件名单拒绝自绘皮肤。

除必要操作和唯一原生歌词外，封面、背景、装饰、文字与可视化可省略或多实例组合，位置和结构由作者控制。Swift 作者可使用任意 SwiftUI 布局与共享数据读取；JSON 作者可以调用已编译组件及轻量布局树。任意外部新 Swift 实现仍需要编译进 App；当前 ZIP 不能据此宣称具备外部脚本执行、完整 Web/Folium 兼容或独立 SDK。

## 可维护性判断

新场景主链路较清楚：`SkinSceneHost` 组合内容、歌词与资源，`SkinSceneControlHost` 管理临时面板/获准动作，包服务负责安装，领域服务负责实际操作。组件工厂使用明确交互能力；增加新组件无需补宿主名单。参数按声明解析，不向稳定上下文累加具体效果字段。

仍有三项维护债务：

1. `FullscreenPlayerView` 约 4,200 行，仍集中旧预设的主题采样、歌词主题与恢复时序。后续应逐个迁移 owner 与副作用，不能仅拆 extension 或增加皮肤分类布尔值。
2. 五个内置渲染器仍有历史设置/设计画布适配，部分效果内部包含可视化。当前提供完整封面、背景和 overlay 部件；更细的旋钮、素材与效果拆分应按实际作者需求开展，并保留原外观验收。
3. 原生作者接口仍依赖 App 内类型，包内字体/视频、独立组件版本演进、多版本回退、开发目录监听与 Web disposers 没有全部交付。应由实际样例推动下一步契约，避免提前把宿主扩成通用脚本框架。

因此，当前可以作为原生组件/本地 ZIP 的继续开发基础，但不应描述为维护债务已清零，也不应宣称 P0–P4 的所有运行条件全部通过。
