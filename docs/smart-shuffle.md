# 偏好随机播放

偏好随机播放在普通随机的基础上引入用户行为信号，但不把队列变成固定推荐列表。系统对喜欢、完整播放、快速切歌、最近曝光和长期未播放分别建模，再用受限权重完成抽样。

## 目标

算法同时追求三件事：更常播放用户明确喜欢或经常听完的曲目；降低连续快速跳过的曲目出现概率；保留新曲、冷门曲目和久未播放曲目的机会。任何单一信号都不能把概率推到零或无限大。

## 行为信号

| 信号 | 含义 | 方向 |
| --- | --- | --- |
| 手动喜欢 | 用户明确表达偏好 | 强正向 |
| 完整或高比例播放 | 曲目被持续收听 | 正向 |
| 快速切歌 | 当前场景下不想继续收听 | 温和负向 |
| 重复快速切歌 | 负向信号更可信 | 继续降低，但有下限 |
| 最近播放 | 避免短期重复 | 暂时降低 |
| 久未播放 | 提供再发现机会 | 温和提高 |
| 新曲或低样本曲目 | 缺少行为数据 | 保留探索概率 |

快速切歌不能被解释为永久不喜欢。用户可能因为当前情境、队列衔接或误触而跳过；因此负向信号需要衰减，也不能盖过手动喜欢等明确选择。

## 权重模型

每首候选曲目先由长期行为得到 `baseWeight`。完整播放、收听比例、跳过、快速跳过、手动喜欢以及 `negativeDamping` 都在这一步合成；抽样时再加入会话内近邻惩罚、新鲜度和偶发的再曝光放大：

```text
runtimeWeight = baseWeight
              × runtimePenalty
              × freshnessMultiplier
              (× rediscoveryBoost，满足触发条件时)

runtimeWeight >= 0.1
```

基础偏好和运行时权重都有边界。`baseWeight` 当前限制在 `0.65...1.35`，最终运行时权重最低为 `0.1`；手动喜欢提高基础偏好，但仍受同曲、同歌手、同专辑的会话内近邻惩罚与候选排除规则约束。再曝光只在部分权重计算中触发，不是每次抽样的常驻乘子。

## 负向衰减

负向分数随时间回落。新的快速切歌影响最大，旧记录逐渐失去权重；多次跳过会比单次跳过更明显，但使用阻尼函数限制边际影响。

这种设计承认偏好会变化，也避免一次短期行为在数月后仍决定队列。若用户后来完整播放同一首曲目，正向行为可以抵消一部分旧负向信号。

## 探索与再曝光

探索用于处理缺少历史数据的新曲或冷门曲目。它常驻但幅度较小，使算法能够收集新的行为反馈，而不是永远围绕已有高分曲目打转。

再曝光面向久未播放的曲目。大多数时候只提供温和提升，少量抽样中可以获得更明显的放大；这让旧曲有机会重新进入队列，又不会在每次随机播放时强行回归。

探索与再曝光都必须服从最近播放抑制、当前队列去重和不可播放状态过滤。

## 持久化与兼容

偏好信号随曲目资料保存，字段升级要提供保守默认值。没有历史数据的旧曲目从中性权重开始，不能因缺少新字段被当作负向样本。

播放历史、喜欢状态和偏好分数属于用户数据。普通缓存清理不删除它们；重置播放统计时，需要明确哪些偏好字段会一同重置。

## 调参原则

- 先限制单个信号的上下界，再调整不同信号的相对强度。
- 观察队列分布，不只看某首曲目的即时分数。
- 快速切歌保持温和，连续行为靠累积提高可信度。
- 新鲜度与再曝光不能同时把久未播放曲目放大到压过明确喜欢。
- 固定随机种子验证权重变化，避免把随机波动误判为算法改进。

## 设计要点

偏好随机播放是一套概率修正，不是确定性排序。它应当让队列更贴近用户，又保留偶然性；当调参让结果几乎可以提前预测时，随机播放也就失去了意义。
