# App 维护备忘

记录日期为 2026-10-04，审查基线为 `f9e4e95b`。范围为 macOS App 本体与本地配套组件，服务端和网站另行维护。本文记录后续工作，实施前重新核对当前调用链和实际行为。

主 App 当时有 441 个 Swift 文件，共 230,826 行，包含注释、空行、自检和采样数据。55 个文件超过 1,000 行，17 个超过 2,000 行。行数用于定位维护热点，不作为运行性能或设计质量的直接证明。

## 后续拆分

| 优先级 | 位置 | 已观察到的问题 | 建议切入点 |
| --- | --- | --- | --- |
| 高 | `Services/Automation/AutomationIPCServer.swift` | 文件约 12,000 行，`execute` 方法接近 6,700 行；协议处理与多个领域的业务编排集中在同一入口 | 先抽一个领域的处理器。入口保留认证、参数约束、幂等、审计、取消和分发；处理器调用现有 App 服务 |

| 中 | `Views/Fullscreen/FullscreenPlayerView.swift` | 文件约 5,700 行，包含大量局部状态，以及歌词主题、背景捕获、重试和事件监控 | 留待实际运行验收条件具备时处理。先区分布局、输入适配、主题协调和宿主生命周期，再按职责拆分 |

每次只迁移一个职责，保留现有状态 owner、命令入口、失败补偿和 session generation 约束。仅拆成多个 extension 可以改善阅读，但不能代替职责调整。完成条件是调用链与行为保持清楚，文件行数下降只作辅助观察。

自动化拆分应选取代表性的只读查询、写操作、重复请求和取消路径做核心回归。资料库拆分应覆盖受影响的提交、回滚和切库失效结果，不借机扩大为整个仓库的重构。

## 发布与开发工具

`PlayerViewModel` 的多个命令会强制更新 Now Playing，`PlaybackCoordinator` 随后刷新 presentation 并再次发布。后续收敛命令完成后的发布职责，核对本地、Apple Music 和系统 Now Playing 三种来源；保留异步音频准备完成时的同步入口。直接删除下层通知可能影响恢复队列、设置同步或独立调用，应先列出这些调用点。

`Services/Audio/SpectrumRecorder.swift` 在本次检查中没有找到外部调用。后续决定恢复明确的开发工具入口，或从 App target 移出；移动时核对它与共享音频分析服务的关系。`Models/SpectrumFrames.swift` 仍被外部播放频谱模拟器使用，保留其数据用途。是否改成二进制资源，应以编译耗时和读取成本为依据。

`Utilities/ColorSystemSelfCheck.swift` 约 5,300 行，受 Debug 和环境变量门控。后续按颜色数学、策略和渲染拆分；纯逻辑可移入测试目标，需要 App 环境的自检保留独立入口。它没有正常启动时的全量执行成本，整理目标是降低维护成本和明确执行方式。

## 验证范围

新增测试应验证可观察行为、事务结果或生命周期边界，不用源码文本、函数数量或文件长度作为正确性断言。常规改动的增量 Debug 构建和编译型测试由维护者运行；符合仓库重大工程变更标准时，Agent 可在实现完成后做一次最终 Debug build-only 编译，但不运行测试。可用完成信号替代固定等待时，采用完成信号；取消测试中的长等待不等同于固定耗时，应检查真实执行路径。

资料库迁移、导入去重、持久化补偿、切库和后台任务停止属于核心覆盖，精简时保留。完整 `verify.sh` 由维护者在合并、PR 或发布门禁阶段手动运行；Agent 的重大工程变更编译例外不包含该门禁，只有用户于当前任务明确要求时运行。每次记录实际执行的检查，不把未运行的测试记为通过。

UI 布局、颜色、动画、歌词可读性和全屏效果以主 App 实际运行检查为准。本轮不新增 UI 自动化或截图快照测试。以后若修改全屏相关代码，分别人工检查系统全屏、窗口模拟全屏和主窗口内嵌，构建成功不代表视觉验收完成。

本轮小范围清理包括删除无调用的废弃随机队列与旧歌单成员 API、移除低于当前部署版本的核心可用性分支，并将两项资料库监控测试改为事件通知等待。大规模拆分、播放发布职责收敛和颜色自检迁移保留在本文，待后续安排。
