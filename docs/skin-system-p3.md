# P3 组件与自由场景实施记录

实施日期为 2026-10-05，承接 [P0–P2 基础重构](skin-system-p0-p2.md)。P3 正在按维护者的实际反馈修正组件接入。原始实现遗漏了完整控制栏与必要入口，不能视为已验收；修正范围与待确认路径见下方。

## 已确认的产品决定

| 项目 | 维护者决定 |
| --- | --- |
| 范围 | 播放页、系统全屏、窗口模拟全屏与主窗口内嵌；P3 先开放原生组件，Web 在 P5 接入 |
| 数量 | 多个封面、装饰、频谱或 LED；一个可见场景最多一个原生歌词组件 |
| 排版 | 作者自由组合，自行决定自适应；普通用户只导入、选择和使用 |
| 样例 | 歌词主导、封面主导、上下布局；开发入口提供，现有内置外观保持 |
| 操作 | 复用现有播放、切歌、进度、音量、喜欢和队列；保留播放器服务与全局快捷键 |
| 样式与输入 | 允许组件颜色与字体覆盖，遵守减少动态效果；局部拖拽、滚轮归组件，App 保留退出、恢复入口 |
| 参数 | 作者标记的少量重要参数放在既有“{skinName} 选项”区；没有批准的内置联动效果不新增默认旋钮 |
| 内置皮肤 | 同样登记为皮肤包，提供可复用组件，导出按钮置灰；内置原件保留，没有删除入口 |
| ZIP 启用 | 加入皮肤列表，由用户选择；导入不自动切换 |
| 身份冲突 | 内置包导回后生成副本；已安装用户皮肤由用户选择替换或另存副本 |

本阶段顺带提前实现了 P4 中已获批准的原生 ZIP 安装与导出子集。原生重载、删除与参数升级兼容在本次审查补齐，市场和开发目录监听按后续阶段推进。

## 职责与接入

| 入口 | 当前职责 |
| --- | --- |
| `SkinScene` / `SkinSceneSnapshot` / `SkinViewport` | 原生作者布局与稳定展示输入；实际视口独立于旧封面画布 |
| `SkinComponentCatalog` / `SkinComponents` | 以字符串身份登记组件工厂，解析组件配置和参数绑定；新增组件不扩宿主的皮肤分类 |
| `SkinSceneDocument` / 独立 Coding 文件 | JSON 的轻量原生组合树，布局映射为 SwiftUI；序列化词汇独立于 Swift 枚举实现 |
| `SkinSceneHost` | 路由获准动作、保留退出/Quick Panel 入口和右键恢复、队列面板与普通侧栏接管 |
| `SkinNativeLyricsMount` / `SkinSceneNativeLyricsLifecycle` | 普通布局容器借用唯一歌词 view；宿主协调激活、设置和作者覆盖 |
| `NativeLyricsSurfaceManager` | 继续持有渲染器、播放快照、配置；作者覆盖叠在 App 配置之后，清除后恢复 App 当前设置 |
| `SkinPresetComponent` | 将内置封面、背景、装饰分别登记为可复用组件，保留原生视觉实现与画布缩放 |
| `SkinMiniPlayerComponent` / 播放附件组件 | 复用完整原生三胶囊，按可用区域调整原生尺寸；中间胶囊不独立登记 |
| `PlaybackTransportControls` | 普通与全屏共用播放/切歌按钮呈现，接收状态、尺寸、颜色与回调 |
| `SkinPackageManifest` / `PackagedSkin` | 内置与安装定义共用包适配；原点只决定管理方式，原生预设保留兼容入口 |
| `SkinPackageStore` | ZIP 解压、解析、资源持久化、登记、导出、身份冲突；新安装准备完成后再替换旧目录 |
| `SkinParameterDefinition` / `SkinParameterStore` | 参数声明、按皮肤与显示模式保存、默认值与实时更新 |
| 设置面板组件 | 使用既有设置行、胶囊选择与按钮；只负责面板、选择状态和用户可见参数 |

普通播放页和各全屏路径在有 `scene` 时使用统一场景宿主，否则继续既有预设布局。五个内置皮肤通过 `registerBundled` 接入同一 catalog，内置导出禁用，提供 `builtin.<id>.artwork`、`.background`、`.overlay`。其既有设置适配仍保留；P3 没有重写每个内置效果的内部实现。

ZIP 中的原生预设引用 App 已编译的实现，原生组件组合包则直接解释 JSON 场景。导出不会把原生可执行代码或 App 内资源复制进 ZIP。任意新 Swift 实现需要编译入 App；任意外部 Web 实现在 P5 接入，当前不宣称兼容 Folia/Folium。

## 自适应与资源归属

- 场景拿到的是播放区域的实际逻辑点尺寸。横向、纵向、叠放、锚点、局部尺寸、层级、偏移与宽窄分支归作者。
- 歌词在布局树内参与遮挡、命中和裁剪，其 `NSView` 按实际区域排版。换布局容器时继续借用同一个 manager-owned 渲染器，旧容器拆除不移走已进入新容器的 view。
- 内置封面效果作为组件时，保留原来的全屏设计画布、资源清晰度输入与局部等比缩放。文字与原生歌词不跟随整个场景缩放。
- 自由场景接管普通歌词时临时收起 inspector，保留原侧栏可见性和宽度；离开后恢复。隐藏的普通宿主停止重复挂载同一 `.main` view。
- 进度观察实时展示的叶节点，稳定场景快照不放时钟和音频帧；新增频谱与 LED 组件共用已有分析服务，并响应场景活跃状态。自由场景接管后卸载原窗口 mini player，背景也由作者场景提供。
- 全屏仍由现有协调器负责播放与歌词配置。作者字体/颜色覆盖由唯一歌词 manager 叠加，避免切歌或主题更新把覆盖冲掉；减少动态效果优先。
- 新场景的设置只展示其声明的选项。旧固定布局的艺术背景、mini player 自动隐藏和封面缩放项不当作任意场景的全局布局参数。

## 维护者反馈后的修正

- `SkinMiniPlayerComponent` 使用左操作胶囊、完整中间播放器和右音量胶囊，移除原来的简化播放器与独立音量条拼接。左操作胶囊与旧全屏底栏共用 `FullscreenLeadingControlsPill`；提供独立左右胶囊、单个播放按钮与原播放顺序滑块。
- `SkinSceneControlHost` 专门负责动作适配、编辑/详情/设置面板、Quick Panel 和必要入口；场景宿主只负责内容、歌词生命周期与包资源。Artwork Scene 的左胶囊提供明确的全屏入口，三个样例均包含歌词，分别展示完整播放器、独立胶囊与细分控件组合。
- 移除可见刷新/恢复按钮，空白处右键刷新场景或恢复外观。无左胶囊的全屏场景由宿主补上退出与 Quick Panel；退出保留系统全屏及内嵌宿主的既有路由。
- `SkinSceneHitRegions` 采集实际控件矩形，让 native 歌词挂载在覆盖区域返回 nil。自由场景停用旧固定画布的 Mini Player 鼠标遮挡矩形；自绘控件可主动声明交互区。
- 封面支持艺术边缘、圆角、模糊和适配模式；背景独立使用纯色、封面、渐变或内置背景；原生歌词补齐常见特性与上下边缘淡出配置。
- `SkinPlaybackReader`、`SkinLyricsReader`、`SkinAudioReader` 提供自绘入口。原图来自现有展示快照，歌词文档来自唯一 owner，音频取共享 Hub 的真实 FFT/PCM 窗口；外部来源明确无真实 PCM。官方 waveform 组件实际使用这个数据入口。
- 内置包导出在设置与服务均禁用；用户包仍可导入/导出。未增加测试、安全机制或外部 Web 执行。

本轮包含追加 hover 与示例要求的增量 Debug 构建通过，已通过标准脚本启动修正版；主进程路径与 PID 见运行记录。按钮、动画与视觉仍不能仅凭源码修改视为通过。


### 追加的示例与胶囊要求

左右胶囊在整组及独立调用时均默认收起，hover 展开、离开延迟 180ms 收起；拖动音量时不收起。复用 `FullscreenBottomControlsCoordinator` 和 `FullscreenBottomControlsAnimationPolicy` 的原动画事务，几何动画与控件颜色/原生绘制隔离，遵守减少动态效果。每个组件实例有自己的暂态 hover 状态，完整播放器内部共享一套两侧状态。

只在 Artwork Scene 使用完整 Mini Player；Lyrics Scene 使用独立左右胶囊与播放按钮，Vertical Scene 使用细分控件。所有 native 歌词示例启用边缘淡出，边缘透明度为 0；Lyrics/Artwork 上下各 12%，Vertical 上 12%、下 16%。开发场景与公开 JSON 同步。

## 顶部交互与 Vertical Scene 修正

2026-10-05 追加修正保留按钮原位置。问题涉及完整内容窗口的 HostingView safe area 与 AppKit 标题栏拖动命中，不能通过改变皮肤位置解决。窗口模拟全屏与主窗口内嵌/系统全屏的专用容器统一使用 `FullscreenPlayerHostingView`，关闭宿主 safe area 与自动拖动，由顶部空白明确触发窗口拖动。官方控件和面板共用实际交互矩形，普通 SwiftUI/AppKit 控件也通过可访问性命中识别，自绘控件沿用 `.skinControlRegion()`。

维护者已确认 21:26 启动版本中，顶部原位置按钮可以点击，顶部空白可以拖动。该确认覆盖维护者当时操作的路径；尚未逐一验收所有三条全屏路径与所有内置外观。

Vertical Scene 重新按封面、曲目信息、歌词与底部控制区组织。播放顺序组件内部的 GeometryReader 没有固有尺寸，导致此前被拉成贯穿窗口的巨大胶囊；组件现在提供原生默认尺寸，作者仍可覆盖宽高。封面裁剪实际适配后的图像矩形，修正 fit 模式圆角丢失。歌词与进度分别限制阅读宽度，控制区使用正常尺寸与间距，歌词保留上下淡出。

自适应节点增加可选 `minimumHeight`，旧 JSON 缺省为 0，宽度分支行为保持。Vertical 的宽窄分支里再嵌套高度分支：窄区域收起封面，矮区域用 112 点封面，高度充足用 204 点封面，歌词占剩余空间。Swift 样例、公开 manifest 与本地 ZIP 同步；没有新增用户参数或宿主皮肤专用分支。

最终高度分支的增量 Debug 构建通过，日志为 `build/logs/skin-vertical-height-debug.log`。第一次构建使用了歌词编译缓存，启动前置因日志缺少本地编译输入而停止；仅移除 DerivedData 中一个 MelismaKit 目标文件后重建，本地 `NativeLyrics/Sources/MelismaKit` 输入检查通过。标准脚本确认单一主进程 PID `9260`，启动于 `2026-10-05 21:41:43`，仍使用上文的 Debug 二进制路径与开发样例参数。

Checkpoint：顶部点击与拖动已由维护者确认；21:26 主 App 实际截图读到正常尺寸控件与新布局，但矮窗口歌词空间仍偏少，随后补充高度分支。最后版本已构建并启动，界面读到主 App 正常播放；界面工具因维护者正在操作窗口而拒绝后续动作，最终高度分支的视觉效果尚未现场确认。本轮没有新增测试或安全工作。
