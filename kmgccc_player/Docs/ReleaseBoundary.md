# 公开构建与资源边界

本目录中的说明只描述公开工程能够保证的行为。公开仓库的源码、提交历史和公开 App 不包含任何未纳入公开发布范围的 shader 源码、Metal 编译产物、艺术原图、加密资源、解密密钥或构建输出。

## 公开运行行为

- Bokeh 渲染宿主只通过稳定的资源契约寻找已编译运行时资源。
- 资源缺失、校验失败、架构不匹配或 ABI 不匹配时，渲染器回退到公开实现，不阻塞播放器启动和播放。
- 艺术资源无法读取时使用公开 fallback，不把原图或解密实现编译进公开目标。
- 公开构建使用 `scripts/build_public.sh`，构建前会关闭外部资源注入，并扫描最终 App。

## 发布禁止项

以下内容不得进入公开工作树、提交历史、标签、分支或 App bundle：

- 未公开的 `.metal`、`.air`、`.metallib` 和相关 shader 参数实现；
- 未公开的 PNG、JPEG、HEIC、WebP、加密艺术资源和资源 manifest；
- 解密密钥、密钥派生材料、解密实现和原始艺术素材；
- 外部构建目录、临时 App、DerivedData、缓存索引和测试输出；
- 能够指向未公开资源源目录的本地路径、命令或提交说明。

## 提交前检查

在创建公开提交前，至少执行：

```sh
scripts/audit_public_release.sh --ref HEAD
scripts/build_public.sh Release
git diff --check
```

对公开远端 refs 做发布前检查时，分别审计公开分支和标签，不要把本地临时分支直接推送到公开仓库。提交标题和正文只描述公开代码的行为，不记录内部资源来源、内部构建布局或未公开实现。

## 事故处理

一旦发现未公开内容进入公开历史：

1. 立即停止继续推送相关 refs。
2. 从公开 refs 和历史中删除相关路径及对象，并重新执行完整审计。
3. 对可能暴露的密钥、签名材料或资源访问凭据进行轮换。
4. 强制更新公开 refs 后，再检查 GitHub 分支、标签、代码搜索和 raw 文件地址。

仅删除当前工作树文件不算完成；只要旧提交仍被公开 ref 指向，就仍然属于公开泄露。
